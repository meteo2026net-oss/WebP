# ECMWF Data Collector — نظام تنزيل ومعالجة وعرض البيانات الجوية

الهدف هو بناء مسار متكامل: **تنزيل GRIB من ECMWF ← فحص الحقول ← تحويلها إلى طبقات جغرافية ← عرضها على خريطة تفاعلية**.


## الإصدار الثاني — خط الأساس والقرارات المعتمدة

تم تثبيت قرارات إصدار ECMWFWebP V2: تطبيق Windows Desktop، واستراتيجية بيانات Hybrid متعددة الاتصالات مع تجميع مركزي اختياري، وواجهة تجمع بين مساحة الأرصاد وإدارة البيانات. راجع [خط أساس الإصدار الثاني وخارطة التنفيذ](docs/ECMWFWEBP_V2_BASELINE_AR.md) لمعرفة الموجود فعلياً والفجوات وخطة حماية البيانات.

## مكونات المشروع
- `src/ecmwf_collector/`: الاتصال بالخادم، استعراض الملفات، التنزيل والاستكمال والتحقق.
- `src/ecmwf_collector/gui/`: واجهة سطح المكتب العربية.
- `src/ecmwf_collector/tools/`: فحص GRIB والتحويل والمعالجة الجماعية.
- `map_viewer/`: واجهة الخريطة التفاعلية المبنية على Leaflet.
- `tests/`: اختبارات آلية وبيئة FTP وهمية.
- `docs/`: التوثيق الفني.
- `config/settings.example.json`: نموذج إعدادات آمن.
- `archive/`: الأرشيف الأصلي للمرحلة الثانية.

## التثبيت الموصى به على Windows

لأن ecCodes وcfgrib يعتمدان على مكتبات ثنائية، أضفت بيئة conda جاهزة لتسهيل التثبيت:

1. ثبّت Miniforge من [المشروع الرسمي](https://github.com/conda-forge/miniforge).
2. افتح طرفية جديدة داخل مجلد المستودع.
3. شغّل `setup_conda.bat` لإنشاء البيئة وفحص ecCodes وcfgrib.
4. شغّل `run_collector_conda.bat` لفتح البرنامج.

### بديل التثبيت باستخدام pip
```powershell
py -3.12 -m venv .venv
.venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item config/settings.example.json config/settings.json
python main.py
```

أدخل بيانات ECMWF داخل التطبيق فقط. لا ترفع كلمة المرور أو ملف الإعدادات المحلي أو قاعدة البيانات أو ملفات GRIB المقيدة إلى GitHub. يفضّل FTPS/TLS؛ FTP العادي غير مشفر.

## تشغيل سريع على Windows
- `run_collector.bat`: تشغيل برنامج التنزيل.
- `process_downloads.bat`: معالجة ملفات GRIB المنزلة وإنشاء الطبقات.
- `start_map.bat`: تشغيل الخريطة التفاعلية محلياً وفتح المتصفح.

## سير العمل الكامل

### 1. تنزيل البيانات
شغّل `python main.py`، ثم أدخل بيانات اتصال WMO Support، اختبر الاتصال، استعرض المجلدات، وحدد المنتجات والفترة، ثم نزّل الملفات. يحفظ البرنامج الملفات الأصلية محلياً في مجلد التنزيل.

### 2. فحص ملف GRIB
```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.tools.inspect_grib path/to/file.grib2 --output output/inventory.json
```

### 2.1 جرد جميع ملفات WMO (AND / FMD / FPD / FSD)

للمجموعات الكبيرة (17 GiB أو أكثر)، أنشئ فهرساً محلياً يحسب الحجم لكل نوع، وبصمات SHA-256، ويكشف النسخ المتطابقة، ويفحص رسائل GRIB وحقولها عند توفر ecCodes:

```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.tools.catalog_grib "E:\\ECMWF\\downloads" --output output/grib_catalog.json
```

تقرأ الأداة الملفات بكتل 4 MiB ولا تحذف الملفات الأصلية أو المكررة. يمكن مراجعة التفاصيل وخيارات التشغيل في [دليل فهرسة GRIB](docs/GRIB_CATALOG.md). لا ترفع ملف الفهرس المحلي أو ملفات WMO المقيدة إلى مستودع عام.


### 2.3 تنزيل NOAA GFS وGEFS

أضيفت واجهتان مستقلتان لتنزيل منتجات NOAA/NCEP بصيغة GRIB2 مباشرة من NOMADS: GFS بدقة 0.25° وGEFS بدقة 0.50° مع اختيار العضو التجميعي. راجع [دليل NOAA GFS وGEFS](docs/NOAA_GFS_GEFS_AR.md) لمعرفة دورات التشغيل وساعات التنبؤ والأعضاء وحدود التحقق والتوافر. هذا التكامل لا يحتاج إلى مفتاح API، ولا يعني أن كل دورة أو ساعة متاحة دائماً.
### 2.2 مصدر ECMWF Open Data والمقارنة مع WMO

أصبح المشروع يدعم مصدرين مستقلين: WMO Support عبر FTP/FTPS، وECMWF Open Data العام عبر مكتبة `ecmwf-opendata`. لا تستخدم بيانات اعتماد WMO للمصدر العام. ثبّت الاعتمادية ضمن بيئة المشروع، ثم نزّل حقولاً محددة فقط:

```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.sources.ecmwf_open_data --time 0 --step 24 --param 2t msl --type fc --output downloads/ecmwf_open_data/ifs_00_step24.grib2
```

لمقارنة ملف من كل مصدر (يلزم تطابق المتغير والمستوى ووقت الصلاحية والشبكة والوحدات):

```powershell
python -m ecmwf_collector.tools.compare_grib_sources "WMO_FILE" "ECMWF_FILE" --output output/source_comparison.json
```

التقرير يميز سلامة الملف من المقارنة العددية، ويحسب الانحياز وMAE وRMSE والتغطية والارتباط للحقول القابلة للمقارنة. هذه المقاييس تقيس الاختلاف بين المصدرين ولا تثبت صحة التنبؤ؛ تقييم الدقة يحتاج بيانات رصد مستقلة. التفاصيل في [دليل المصدر والمقارنة](docs/ECMWF_OPEN_DATA_COMPARISON.md).

### 3. تحويل الحقول إلى طبقات خريطة
```powershell
python -m ecmwf_collector.tools.grib_to_map path/to/file.grib2 --output-dir output/map_data
```
يحوّل الحقول العددية ذات إحداثيات 1-D المنتظمة أو إحداثيات جغرافية 2-D مطابقة إلى PNG شفاف، ويفصل أبعاد زمن التنبؤ والمستويات الرأسية إلى طبقات مستقلة متى كانت متاحة، وينشئ ملفات JSON وNPZ وقائمة `manifest.json`. للشبكات ذات الإحداثيات 2-D يستخدم إحداثيات خطوط الطول والعرض التي يفكها cfgrib لإعادة الإسقاط إلى Web Mercator.

### 4. معالجة جميع الملفات المنزلة
```powershell
python -m ecmwf_collector.tools.process_downloads --downloads downloads --output-dir output/map_data
```

### 5. تحويل الرياح U/V
```powershell
python -m ecmwf_collector.tools.wind_grib_to_webp path/to/wind.grib2 --output output/wind.webp
```
ينتج WebP علمياً مشفراً، وPNG لسرعة الرياح، ويسجل طبقة العرض تلقائياً في manifest. يدعم شبكات 1-D المنتظمة وشبكات geolocation ثنائية الأبعاد عندما يوفرها cfgrib. يسجل اتجاه الرياح وفق اصطلاح الأرصاد (الاتجاه الذي تأتي منه الرياح، درجات مع عقارب الساعة من الشمال)؛ اتجاه الرياح الساكنة غير معرّف. يتحقق المحول من تطابق وحدات U وV ولا يفترض m/s عند غياب الوحدة. كما يسجل ما إذا كانت المركبات مرتبطة بمحاور الشبكة؛ لا يجوز تفسير اتجاه المركبات الشبكية كاتجاه جغرافي قبل تدويرها إلى الإطار الأرضي. WebP ذو 8-bit منتج مضغوط للعرض/النقل وليس بديلاً عن GRIB للحسابات الدقيقة.

### 6. فتح الخريطة التفاعلية
من جذر المستودع:
```powershell
python serve_map.py
```
ثم افتح:
`http://127.0.0.1:8765/map_viewer/`

تستطيع اختيار الطبقة، تغيير شفافيتها، وتكبير نطاقها. انقر على أي نقطة في الخريطة لاستخراج قيمة من بيانات GRIB الأصلية مع الوحدة ووقت الصلاحية. يمكن اختيار أقرب خلية شبكية أو الاستيفاء الثنائي بين أربع خلايا متجاورة؛ يرفض الاستيفاء الثنائي الاستقراء خارج مراكز الشبكة أو الحساب عند وجود قيم مفقودة في الزوايا المطلوبة. عند توفر عدة أزمنة للحقل نفسه يظهر شريط زمني للتنقل بين إطارات التنبؤ وزر لتشغيلها بالتتابع. يلزم تشغيل الخادم المحلي لأن المتصفح لا يقرأ manifest عبر `file://` مباشرة.

## الحدود الحالية
- يدعم محرك الخريطة الشبكات المنتظمة ذات إحداثيات 1-D، كما يدعم الشبكات الإقليمية ذات إحداثيات latitude/longitude ثنائية الأبعاد عند توفيرها من cfgrib، بما فيها كثير من منتجات Lambert وrotated-pole وpolar stereographic.
- إعادة إسقاط الشبكات 2-D تعتمد على geolocation المفكوك ولا تخمّن معاملات الإسقاط. تستخدم الاستيفاء الخطي داخل الغلاف المحدب وتترك الخارج شفافاً؛ الشبكات الإقليمية المنحنية التي تعبر خط التاريخ الدولي مدعومة عندما يبقى أقصر امتداد دائري لخطوط الطول ضمن 180 درجة؛ تُفك خطوط الطول إلى مجال متصل قبل الإسقاط، وتُحفظ حدود الخريطة دون تطبيع خاطئ عند ±180°. أما الشبكات العالمية المنحنية التي يتجاوز امتدادها 180 درجة فتُرفض حالياً بأمان حتى تنفيذ مسار تقسيم إلى بلاطات ومعالجة seam-aware. كما تُرفض إحداثيات خطوط الطول المنحنية خارج المجال الزاوي المعتاد من ‎-360° إلى ‎360° بدلاً من السماح لقيم شاذة بإفساد إعادة الإسقاط.
- استخراج القيم عند النقر يدعم أقرب خلية للشبكات 2-D، بينما الاستيفاء الثنائي متاح حالياً للشبكات المنتظمة 1-D فقط.
- يجب التمييز بين عرض الشبكة المنحنية والاستعلام عن نقاطها: عرض الشبكات المنحنية العالمية التي يتجاوز امتدادها 180 درجة غير مدعوم بعد ويُرفض بأمان، لكن استعلام أقرب خلية على شبكة geolocation ثنائية الأبعاد يمكنه التعامل مع شبكة عالمية. هذا لا يعني أن العرض العالمي أو الاستيفاء الثنائي للشبكات 2-D مدعومان.
- ليست كل ملفات GRIB قابلة للفتح في مجموعة واحدة؛ بعض الملفات تحوي مجموعات حقول مختلفة، وقد تتطلب تحديد المتغير أو فصل الرسائل.
- WebP الحالي يستخدم quantization بدقة 8-bit؛ احتفظ بملفات GRIB الأصلية للحسابات العلمية.
- لم يُختبر الاتصال الحقيقي بـ ECMWF أو عرض بيانات ECMWF فعلية بعد؛ يلزم إجراء اختبار تكاملي باستخدام ملف GRIB مسموح بتداوله.
- يتوفر اختبار تكاملي يدوي عبر GitHub Actions باسم `ECMWF real GRIB2 smoke test`. بعد دمج workflow افتح تبويب Actions، اختر الاختبار، اضغط Run workflow واترك المتغير `msl` للملف التجريبي الموثق. لا تعتبر الاختبار ناجحاً إلا بعد نجاح مهمة `real-grib2-smoke`؛ نزّل artifact الخاص بالتشغيل وافحص `SHA256SUMS.txt` و`inventory.json` و`validation-summary.json` ومجلد `map/`. هذا الاختبار يتحقق من ملف ECMWF الثابت المحدد فقط، ولا يثبت وجود تغذية تشغيلية مباشرة.


**تنبيه لاتجاه الرياح:** صيغة اتجاه الرياح من (FROM) صحيحة فقط عندما تكون U موجبة نحو الشرق وV موجبة نحو الشمال؛ إذا كانت المركبات مرتبطة بمحاور الشبكة فيجب تدويرها إلى مركبات أرضية أولاً. لا يُسند اتجاه للرياح الساكنة.

### النسخ الاحتياطي التلقائي واليدوي لسجل SQLite

- قبل فتح قاعدة البيانات عند بدء التطبيق، ينشئ البرنامج نسخة يومية تلقائية إذا كانت قاعدة SQLite موجودة. لا ينسخ قاعدة جديدة فارغة، ولا يوقف تشغيل البرنامج إذا فشل النسخ؛ يسجل الخطأ ويترك قاعدة البيانات الأصلية دون تعديل.
- تحفظ النسخ في `%LOCALAPPDATA%\\ECMWFWebP\\state\\backups` في النسخة المحمولة، أو داخل `state/backups` عند التشغيل من المصدر.
- تُفحص كل نسخة بواسطة `PRAGMA integrity_check` ويُتحقق من وجود جدول `files` قبل اعتمادها. تُنشأ النسخة المؤقتة أولاً ثم تُنقل ذرياً إلى اسمها النهائي.
- يحتفظ التطبيق بآخر 30 نسخة يومية وآخر 30 نسخة يدوية. التدوير يطال ملفات النسخ التابعة للتطبيق فقط، ولا يلمس قاعدة البيانات الأصلية.
- أضيف زر **نسخ احتياطي للسجل** لإنشاء نسخة يدوية والتحقق منها، وزر **استعادة نسخة SQLite** لاختيار نسخة صالحة واستعادتها. قبل الاستبدال ينشئ التطبيق نسخة أمان من السجل الحالي، ويرفض الاستعادة إذا بقي ملف WAL/SHM جانبياً، ثم يعيد فتح قاعدة البيانات. استعادة النسخ متاحة حالياً لـ SQLite فقط؛ أما PostgreSQL فأضيف له نسخ احتياطي مخصص عبر `pg_dump` بصيغة custom، مع فحص الأرشيف بواسطة `pg_restore --list` قبل نشره، وإنشاء ملف JSON جانبي لكل نسخة يتضمن قاعدة البيانات والتوقيت والحجم وبصمة SHA-256 للتحقق من عدم تلف الملف أو تغييره، وتدوير آخر 30 نسخة مع ملفاتها الوصفية. يتطلب ذلك وجود `pg_dump` و`pg_restore` من إصدار PostgreSQL متوافق. يتحقق التطبيق أولاً من تطابق الإصدار الرئيسي لأداتي `pg_dump` و`pg_restore` لتجنب إنشاء نسخة بأدوات غير متوافقة، ويكتشف تلقائياً أدوات Windows في مجلدات التثبيت المعتادة `Program Files\\PostgreSQL\\<version>\\bin`، كما يبحث في `PATH`. يمكن تجاوز الاكتشاف بتحديد `ECMWF_PG_DUMP` و`ECMWF_PG_RESTORE` أو اختيار المسارين صراحةً في إعدادات البيئة. لا تمر كلمة مرور قاعدة البيانات في سطر أوامر العملية؛ تُمرر عبر بيئة العملية فقط. تُحفظ الملفات داخل `state/backups` ولا يحذف النسخ أو يعدّل بيانات PostgreSQL الأصلية.

## PostgreSQL المحلي وترحيل سجل التنزيلات

أُضيف backend اختياري لـ PostgreSQL مع الحفاظ على SQLite كخيار افتراضي آمن:
- يستخدم التطبيق SQLite محلياً افتراضياً. بعد تثبيت خادم PostgreSQL وإنشاء قاعدة بيانات محلية، اضغط `ربط PostgreSQL ونقل السجل` وأدخل سلسلة اتصال حساب مدير يملك صلاحيات إنشاء الأدوار ومنح الصلاحيات (الإدخال مخفي). ينشئ التطبيق حساباً مستقلاً باسم `ecmwf_webp_app` بكلمة مرور عشوائية، مع تعطيل صلاحيات superuser وإنشاء قواعد البيانات والأدوار والنسخ المتماثل وتجاوز سياسات RLS؛ ويمنحه الاتصال بقاعدة البيانات واستخدام مخطط `public` فقط. ينشئ المدير جدول `public.files` مسبقاً ويظل مالكاً له، ثم يحصل حساب التطبيق على صلاحيات `SELECT/INSERT/UPDATE/DELETE` على هذا الجدول فقط، دون صلاحية `CREATE` على المخطط؛ يُنشئ كلمة المرور باستخدام ترميز SQL آمن ولا يمررها في سطر أوامر النظام. قد يسجل خادم PostgreSQL عبارات DDL وفق إعدادات سجلاته؛ لذلك يجب مراجعة سياسة التسجيل على الخادم وعدم تفعيل تسجيل العبارات الحساسة أثناء الإعداد. يختبر التطبيق الحساب المحدود، ثم ينقل السجلات ويتحقق منها، ويحفظ سلسلة اتصال حساب التطبيق فقط في Windows Credential Manager. لا يحفظ بيانات اعتماد المدير.
- يمكن أيضاً استخدام متغير البيئة `ECMWF_POSTGRES_DSN` للتشغيل المتقدم؛ عند وجوده تكون له الأولوية على الاتصال المحفوظ. يجب أن يحتوي هذا المتغير على اتصال حساب التطبيق محدود الصلاحيات، وليس بيانات اعتماد المدير. يتحقق backend عند كل تهيئة من أن الحساب الحالي ليس superuser ولا يملك صلاحيات إنشاء قواعد/أدوار أو replication أو تجاوز RLS، ويرفض أيضاً العضوية في الأدوار الإدارية المضمنة ذات الصلاحيات المرتفعة مثل `pg_read_all_data` و`pg_write_all_data` و`pg_execute_server_program`. كما يتحقق من وجود `public.files` ومن صلاحيات DML الأربع، ولا ينشئ جداول بصلاحيات حساب التطبيق.
- الاعتمادية `psycopg[binary]` مضمنة في متطلبات Python.
- زر الواجهة هو المسار الموصى به للمستخدم: ينشئ نسخة احتياطية مؤرخة داخل `state/backups/`، ويضيف السجلات غير الموجودة فقط، ويرفض التعارضات، ثم يقارن السجلات للتحقق. لا يحذف SQLite ولا يستبدله.
- للمطورين يمكن تنفيذ الترحيل من الطرفية بعد ضبط `ECMWF_POSTGRES_DSN` أو حفظ الاتصال عبر أداة `configure_postgres`:
```powershell
python -m ecmwf_collector.tools.migrate_sqlite_to_postgres --sqlite state/state.db
```

**تثبيت PostgreSQL على Windows:** يتضمن التطبيق زر `تثبيت PostgreSQL` يستخدم Windows Package Manager (`winget`) لتشغيل مثبّت EDB الرسمي PostgreSQL 16 بوضع تفاعلي. أكمل نافذة المثبّت وحدد كلمة مرور المدير بنفسك؛ لا يمرر التطبيق كلمة مرور افتراضية ولا يحفظ كلمة مرور المدير. بعد التثبيت يعيد التطبيق فحص ملفات الخادم وأدوات العميل وخدمات Windows. إذا لم يكن `winget` موجوداً، ثبّت App Installer من Microsoft Store. يتطلب التثبيت صلاحيات Windows المناسبة واتصالاً بالإنترنت.

**قاعدة البيانات المستهدفة:** المثبّت يهيئ خادم PostgreSQL وخدمته، لكنه لا ينشئ قاعدة تطبيق مخصصة باسم تختاره. أنشئ قاعدة البيانات المطلوبة من pgAdmin أو أداة PostgreSQL الرسمية، ثم أدخل سلسلة اتصال المدير الخاصة بتلك القاعدة في زر `ربط PostgreSQL ونقل السجل`. ينشئ التطبيق جدول `public.files` وحساب `ecmwf_webp_app` محدود الصلاحيات، وينقل السجلات بعد نسخة SQLite الاحتياطية والتحقق منها. تبقى SQLite الأصلية ونسختها الاحتياطية دون حذف.

**استعادة PostgreSQL:** اختر ملف `.dump` المطابق وملف JSON الجانبي الموجود بجانبه. يتحقق التطبيق من الحجم وبصمة SHA-256 وقاعدة البيانات الفعلية التي اتصل بها قبل أي استبدال، ثم ينشئ نسخة أمان من القاعدة الحالية. تتطلب الاستعادة الكاملة سلسلة اتصال حساب `SUPERUSER`؛ حساب مالك قاعدة البيانات وحده غير كافٍ لهذا الإجراء. تُنفذ عملية الاستعادة داخل معاملة واحدة، ثم يعاد منح حساب التطبيق صلاحيات الجدول المحدودة ويُختبر الاتصال به. لا تحذف ملف النسخة الاحتياطية أو ملف JSON الجانبي.


### إعداد اتصال PostgreSQL بأمان

للمطورين في بيئة المصدر، بعد تثبيت خادم PostgreSQL وإنشاء قاعدة البيانات، يمكن استخدام:
```powershell
python -m ecmwf_collector.tools.configure_postgres
```
تطلب الأداة سلسلة اتصال حساب المدير بإدخال مخفي، ثم تنشئ حساب التطبيق محدود الصلاحيات وتتحقق منه، وتحفظ سلسلة اتصال حساب التطبيق فقط في مخزن بيانات الاعتماد الخاص بنظام التشغيل عبر `keyring`؛ لا تحفظ اتصال المدير. لإزالة بيانات اتصال التطبيق المحفوظة استخدم `--remove`. في النسخة المكتبية المحمولة، استخدم زر الربط داخل الواجهة بدلاً من هذه الأوامر. أداة الترحيل تستخدم SQLite Online Backup لالتقاط نسخة متسقة حتى عند وجود WAL أو كون التطبيق مفتوحاً.

## مراجعة المتنبئين وواجهة REST

يتضمن المشروع الآن مكوّناً فعلياً لواجهة WSGI REST لمراجعة التنبؤات، إضافة إلى
خدمة تطبيقية ومستودع PostgreSQL وسجل تدقيق وانتقالات مراجعة محكومة بإصدارات
متزامنة. راجع [دليل واجهة WSGI](docs/REVIEW_API_WSGI_AR.md)،
[حدود الخدمة والصلاحيات](docs/REVIEW_SERVICE_API_BOUNDARY_AR.md)،
[مستودع المراجعة PostgreSQL](docs/POSTGRES_REVIEW_REPOSITORY_AR.md)،
و[سير مراجعة المتنبئين](docs/FORECASTER_REVIEW_WORKFLOW_AR.md).

**الحالة التشغيلية:** الواجهة قابلة للاستدعاء كـ WSGI application وتغطيها
اختبارات عقد HTTP، لكنها ليست خدمة منشورة. لا يوجد مزود هوية إنتاجي مهيأ،
ولا قاعدة مراجعة إنتاجية أو pool اتصالات مضبوط. يجب عدم تعريضها للإنترنت قبل
إضافة تحقق جلسات/JWT موثوق، وحماية CSRF عند استخدام cookies، وTLS، وتطبيق
صلاحيات قاعدة البيانات ومراجعة المنح الموروثة، وتحديد المعدلات والمراقبة.
كما أن واجهة مراجعة المتنبئ الرسومية لم تُربط بهذه المسارات بعد.
