# ECMWF Data Collector — نظام تنزيل ومعالجة وعرض البيانات الجوية

الهدف هو بناء مسار متكامل: **تنزيل GRIB من ECMWF ← فحص الحقول ← تحويلها إلى طبقات جغرافية ← عرضها على خريطة تفاعلية**.

## مكونات المشروع
- `src/ecmwf_collector/`: الاتصال بالخادم، استعراض الملفات، التنزيل والاستكمال والتحقق.
- `src/ecmwf_collector/gui/`: واجهة سطح المكتب العربية.
- `src/ecmwf_collector/tools/`: فحص GRIB والتحويل والمعالجة الجماعية.
- `map_viewer/`: واجهة الخريطة التفاعلية المبنية على Leaflet.
- `tests/`: اختبارات آلية وبيئة FTP وهمية.
- `docs/`: التوثيق الفني.
- `config/settings.example.json`: نموذج إعدادات آمن.
- `archive/`: الأرشيف الأصلي للمرحلة الثانية.

## التثبيت الموصى به على Windows

لأن ecCodes وcfgrib يعتمدان على مكتبات ثنائية، أضفت بيئة conda جاهزة لتسهيل التثبيت:

1. ثبّت Miniforge من [المشروع الرسمي](https://github.com/conda-forge/miniforge).
2. افتح طرفية جديدة داخل مجلد المستودع.
3. شغّل `setup_conda.bat` لإنشاء البيئة وفحص ecCodes وcfgrib.
4. شغّل `run_collector_conda.bat` لفتح البرنامج.

### بديل التثبيت باستخدام pip
```powershell
py -3.12 -m venv .venv
.venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item config/settings.example.json config/settings.json
python main.py
```

أدخل بيانات ECMWF داخل التطبيق فقط. لا ترفع كلمة المرور أو ملف الإعدادات المحلي أو قاعدة البيانات أو ملفات GRIB المقيدة إلى GitHub. يفضّل FTPS/TLS؛ FTP العادي غير مشفر.

## تشغيل سريع على Windows
- `run_collector.bat`: تشغيل برنامج التنزيل.
- `process_downloads.bat`: معالجة ملفات GRIB المنزلة وإنشاء الطبقات.
- `start_map.bat`: تشغيل الخريطة التفاعلية محلياً وفتح المتصفح.

## سير العمل الكامل

### 1. تنزيل البيانات
شغّل `python main.py`، ثم أدخل بيانات اتصال WMO Support، اختبر الاتصال، استعرض المجلدات، وحدد المنتجات والفترة، ثم نزّل الملفات. يحفظ البرنامج الملفات الأصلية محلياً في مجلد التنزيل.

### 2. فحص ملف GRIB
```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.tools.inspect_grib path/to/file.grib2 --output output/inventory.json
```

### 3. تحويل الحقول إلى طبقات خريطة
```powershell
python -m ecmwf_collector.tools.grib_to_map path/to/file.grib2 --output-dir output/map_data
```
يحوّل الحقول العددية ذات إحداثيات 1-D المنتظمة أو إحداثيات جغرافية 2-D مطابقة إلى PNG شفاف، ويفصل أبعاد زمن التنبؤ والمستويات الرأسية إلى طبقات مستقلة متى كانت متاحة، وينشئ ملفات JSON وNPZ وقائمة `manifest.json`. للشبكات ذات الإحداثيات 2-D يستخدم إحداثيات خطوط الطول والعرض التي يفكها cfgrib لإعادة الإسقاط إلى Web Mercator.

### 4. معالجة جميع الملفات المنزلة
```powershell
python -m ecmwf_collector.tools.process_downloads --downloads downloads --output-dir output/map_data
```

### 5. تحويل الرياح U/V
```powershell
python -m ecmwf_collector.tools.wind_grib_to_webp path/to/wind.grib2 --output output/wind.webp
```
ينتج WebP علمياً مشفراً، وPNG لسرعة الرياح، ويسجل طبقة العرض تلقائياً في manifest. يدعم شبكات 1-D المنتظمة وشبكات geolocation ثنائية الأبعاد عندما يوفرها cfgrib. يسجل اتجاه الرياح وفق اصطلاح الأرصاد (الاتجاه الذي تأتي منه الرياح، درجات مع عقارب الساعة من الشمال)؛ اتجاه الرياح الساكنة غير معرّف. يتحقق المحول من تطابق وحدات U وV ولا يفترض m/s عند غياب الوحدة. كما يسجل ما إذا كانت المركبات مرتبطة بمحاور الشبكة؛ لا يجوز تفسير اتجاه المركبات الشبكية كاتجاه جغرافي قبل تدويرها إلى الإطار الأرضي. WebP ذو 8-bit منتج مضغوط للعرض/النقل وليس بديلاً عن GRIB للحسابات الدقيقة.

### 6. فتح الخريطة التفاعلية
من جذر المستودع:
```powershell
python serve_map.py
```
ثم افتح:
`http://127.0.0.1:8765/map_viewer/`

تستطيع اختيار الطبقة، تغيير شفافيتها، وتكبير نطاقها. انقر على أي نقطة في الخريطة لاستخراج قيمة من بيانات GRIB الأصلية مع الوحدة ووقت الصلاحية. يمكن اختيار أقرب خلية شبكية أو الاستيفاء الثنائي بين أربع خلايا متجاورة؛ يرفض الاستيفاء الثنائي الاستقراء خارج مراكز الشبكة أو الحساب عند وجود قيم مفقودة في الزوايا المطلوبة. عند توفر عدة أزمنة للحقل نفسه يظهر شريط زمني للتنقل بين إطارات التنبؤ وزر لتشغيلها بالتتابع. يلزم تشغيل الخادم المحلي لأن المتصفح لا يقرأ manifest عبر `file://` مباشرة.

## الحدود الحالية
- يدعم محرك الخريطة الشبكات المنتظمة ذات إحداثيات 1-D، كما يدعم الشبكات الإقليمية ذات إحداثيات latitude/longitude ثنائية الأبعاد عند توفيرها من cfgrib، بما فيها كثير من منتجات Lambert وrotated-pole وpolar stereographic.
- إعادة إسقاط الشبكات 2-D تعتمد على geolocation المفكوك ولا تخمّن معاملات الإسقاط. تستخدم الاستيفاء الخطي داخل الغلاف المحدب وتترك الخارج شفافاً؛ الشبكات الإقليمية المنحنية التي تعبر خط التاريخ الدولي مدعومة عندما يبقى أقصر امتداد دائري لخطوط الطول ضمن 180 درجة؛ تُفك خطوط الطول إلى مجال متصل قبل الإسقاط، وتُحفظ حدود الخريطة دون تطبيع خاطئ عند ±180°. أما الشبكات العالمية المنحنية التي يتجاوز امتدادها 180 درجة فتُرفض حالياً بأمان حتى تنفيذ مسار تقسيم إلى بلاطات ومعالجة seam-aware. كما تُرفض إحداثيات خطوط الطول المنحنية خارج المجال الزاوي المعتاد من ‎-360° إلى ‎360° بدلاً من السماح لقيم شاذة بإفساد إعادة الإسقاط.
- استخراج القيم عند النقر يدعم أقرب خلية للشبكات 2-D، بينما الاستيفاء الثنائي متاح حالياً للشبكات المنتظمة 1-D فقط.
- يجب التمييز بين عرض الشبكة المنحنية والاستعلام عن نقاطها: عرض الشبكات المنحنية العالمية التي يتجاوز امتدادها 180 درجة غير مدعوم بعد ويُرفض بأمان، لكن استعلام أقرب خلية على شبكة geolocation ثنائية الأبعاد يمكنه التعامل مع شبكة عالمية. هذا لا يعني أن العرض العالمي أو الاستيفاء الثنائي للشبكات 2-D مدعومان.
- ليست كل ملفات GRIB قابلة للفتح في مجموعة واحدة؛ بعض الملفات تحوي مجموعات حقول مختلفة، وقد تتطلب تحديد المتغير أو فصل الرسائل.
- WebP الحالي يستخدم quantization بدقة 8-bit؛ احتفظ بملفات GRIB الأصلية للحسابات العلمية.
- لم يُختبر الاتصال الحقيقي بـ ECMWF أو عرض بيانات ECMWF فعلية بعد؛ يلزم إجراء اختبار تكاملي باستخدام ملف GRIB مسموح بتداوله.
- يتوفر اختبار تكاملي يدوي عبر GitHub Actions باسم `ECMWF real GRIB2 smoke test`. بعد دمج workflow افتح تبويب Actions، اختر الاختبار، اضغط Run workflow واترك المتغير `msl` للملف التجريبي الموثق. لا تعتبر الاختبار ناجحاً إلا بعد نجاح مهمة `real-grib2-smoke`؛ نزّل artifact الخاص بالتشغيل وافحص `SHA256SUMS.txt` و`inventory.json` و`validation-summary.json` ومجلد `map/`. هذا الاختبار يتحقق من ملف ECMWF الثابت المحدد فقط، ولا يثبت وجود تغذية تشغيلية مباشرة.


**تنبيه لاتجاه الرياح:** صيغة اتجاه الرياح من (FROM) صحيحة فقط عندما تكون U موجبة نحو الشرق وV موجبة نحو الشمال؛ إذا كانت المركبات مرتبطة بمحاور الشبكة فيجب تدويرها إلى مركبات أرضية أولاً. لا يُسند اتجاه للرياح الساكنة.


## نسخة Windows المكتبية (حزمة تجريبية ناجحة على CI)

أُضيف مسار بناء Windows x64 باستخدام PyInstaller دون Docker:
- من نسخة المصدر: شغّل `START.bat`. يتطلب مسار البناء الحالي Python 3.12 x64 واتصالاً بالإنترنت لتنزيل الاعتماديات.
- بعد البناء، توجد الحزمة في `dist/ECMWFWebP/` وبداخلها `ECMWFWebP.exe` و`START.bat`. يمكن نقل المجلد كاملاً إلى جهاز Windows x64 آخر وتشغيل `START.bat` دون تثبيت Python أو Git أو Conda.
- عند تنزيل artifact من GitHub Actions، فك ضغط الحزمة كاملة ثم شغّل `START.bat`؛ لا تنقل ملف EXE وحده لأن ملفات التشغيل المساندة موجودة بجانبه.
- ينشئ التطبيق بياناته القابلة للكتابة في `%LOCALAPPDATA%\\ECMWFWebP` عند التشغيل المجمّد؛ لا تُكتب التنزيلات أو الإعدادات داخل مجلد البرنامج.
- ينشئ GitHub Actions حزمة باسم `ECMWFWebP-Windows-x64` تشمل `START.bat` وملف `SHA256SUMS.txt` للتحقق من سلامة ملفات الحزمة. الحزمة التجريبية متاحة من صفحة تشغيل Workflow لمدة 14 يوماً.

**حالة التحقق:** نجح تشغيل Windows CI رقم 86 على commit `30750f7e407496067d527b233ec4c8a050fa6b36`، بما في ذلك بناء EXE واختبار بدء التطبيق لمدة 12 ثانية وفحص صفحة الخريطة وملفي CSS وJavaScript ورفع artifact باسم `ECMWFWebP-Windows-x64`. هذه نتيجة بناء واختبار آلي على GitHub-hosted Windows runner، وليست بديلاً عن تجربة تثبيت وتشغيل على جهاز Windows نظيف مستقل.

**تنبيه:** هذا المسار لا يثبت PostgreSQL ولا يغيّر سجل الحالة الحالي من SQLite. لا تعتبر الحزمة إصداراً نهائياً قبل اختبارها على جهاز Windows نظيف. الإصدار الحالي المستهدف والمبني هو Windows x64؛ دعم ARM64 وmacOS وLinux يحتاج حزم بناء مستقلة.


## PostgreSQL المحلي وترحيل سجل التنزيلات

أُضيف backend اختياري لـ PostgreSQL مع الحفاظ على SQLite كخيار افتراضي آمن:
- يستخدم التطبيق SQLite محلياً افتراضياً. بعد تثبيت خادم PostgreSQL وإنشاء قاعدة بيانات محلية، اضغط `ربط PostgreSQL ونقل السجل` وأدخل سلسلة اتصال حساب مدير يملك صلاحيات إنشاء الأدوار ومنح الصلاحيات (الإدخال مخفي). ينشئ التطبيق حساباً مستقلاً باسم `ecmwf_webp_app` بكلمة مرور عشوائية، مع تعطيل صلاحيات superuser وإنشاء قواعد البيانات والأدوار والنسخ المتماثل وتجاوز سياسات RLS؛ ويمنحه الاتصال بقاعدة البيانات وإنشاء الجداول في مخطط `public` فقط؛ يُنشئ كلمة المرور باستخدام ترميز SQL آمن ولا يمررها في سطر أوامر النظام. قد يسجل خادم PostgreSQL عبارات DDL وفق إعدادات سجلاته؛ لذلك يجب مراجعة سياسة التسجيل على الخادم وعدم تفعيل تسجيل العبارات الحساسة أثناء الإعداد. يختبر التطبيق الحساب المحدود، ثم ينقل السجلات ويتحقق منها، ويحفظ سلسلة اتصال حساب التطبيق فقط في Windows Credential Manager. لا يحفظ بيانات اعتماد المدير.
- يمكن أيضاً استخدام متغير البيئة `ECMWF_POSTGRES_DSN` للتشغيل المتقدم؛ عند وجوده تكون له الأولوية على الاتصال المحفوظ. يجب أن يحتوي هذا المتغير على اتصال حساب التطبيق محدود الصلاحيات، وليس بيانات اعتماد المدير.
- الاعتمادية `psycopg[binary]` مضمنة في متطلبات Python.
- زر الواجهة هو المسار الموصى به للمستخدم: ينشئ نسخة احتياطية مؤرخة داخل `state/backups/`، ويضيف السجلات غير الموجودة فقط، ويرفض التعارضات، ثم يقارن السجلات للتحقق. لا يحذف SQLite ولا يستبدله.
- للمطورين يمكن تنفيذ الترحيل من الطرفية بعد ضبط `ECMWF_POSTGRES_DSN` أو حفظ الاتصال عبر أداة `configure_postgres`:
```powershell
python -m ecmwf_collector.tools.migrate_sqlite_to_postgres --sqlite state/state.db
```

**ما لم ينجز بعد:** تنزيل وتثبيت خادم PostgreSQL نفسه وإنشاء خدمة Windows وقاعدة البيانات تلقائياً. يجب تثبيت الخادم وإنشاء قاعدة البيانات أولاً بصلاحيات مسؤول الجهاز. يقوم زر الربط بعد ذلك بإنشاء حساب التطبيق محدود الصلاحيات تلقائياً. لا نستخدم التثبيت الصامت الافتراضي الذي يترك كلمة مرور معروفة، ولا نضع كلمات المرور في BAT أو Git أو سجلات التشغيل. لا يُدّعى أن PostgreSQL أصبح مثبتاً بمجرد وجود backend.


### إعداد اتصال PostgreSQL بأمان

للمطورين في بيئة المصدر، بعد تثبيت خادم PostgreSQL وإنشاء قاعدة البيانات، يمكن استخدام:
```powershell
python -m ecmwf_collector.tools.configure_postgres
```
تطلب الأداة سلسلة اتصال حساب المدير بإدخال مخفي، ثم تنشئ حساب التطبيق محدود الصلاحيات وتتحقق منه، وتحفظ سلسلة اتصال حساب التطبيق فقط في مخزن بيانات الاعتماد الخاص بنظام التشغيل عبر `keyring`؛ لا تحفظ اتصال المدير. لإزالة بيانات اتصال التطبيق المحفوظة استخدم `--remove`. في النسخة المكتبية المحمولة، استخدم زر الربط داخل الواجهة بدلاً من هذه الأوامر. أداة الترحيل تستخدم SQLite Online Backup لالتقاط نسخة متسقة حتى عند وجود WAL أو كون التطبيق مفتوحاً.
