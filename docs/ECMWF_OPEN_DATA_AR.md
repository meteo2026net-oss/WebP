# تكامل ECMWF Open Data في WebP

هذا الموصل منفصل عن اتصال ECMWF WMO Support FTP الموجود في WebP. وهو يجلب مجموعة محددة من ملفات التنبؤات المفتوحة عبر مكتبة `ecmwf-opendata`، ثم يتحقق من سلامة GRIB قبل نشر الملف النهائي.

## الاستخدام من واجهة Windows

أضيف قسم مستقل بعنوان **بيانات ECMWF Open Data** داخل نافذة البرنامج. اختر النموذج والمصدر والدقة ودورة التشغيل ونطاق ساعات التنبؤ ورموز المتغيرات، ثم اضغط **تنزيل ECMWF وتحويله إلى خريطة**. يدعم IFS وAIFS Single وAIFS Ensemble (عضو واحد تحدده من 1 إلى 50). خيار أحدث دورة متاح مفعّل افتراضياً. لا تُطلب بيانات دخول WMO ولا تُرسل إلى خدمة ECMWF Open Data.

بعد نجاح التحقق من GRIB:
- يسجل البرنامج الملف في قاعدة حالة الملفات المحلية SQLite مع الحجم والبصمة والحالة.
- يحوّل الحقول الجغرافية المتوافقة إلى طبقات داخل `output/map_data`.
- يحدّث `manifest.json` الذي يقرأه عارض الخرائط الحالي.
- إذا فشل تحديث سجل SQLite، يعرض البرنامج تحذيراً واضحاً ولا يحذف الملف الذي تم تنزيله.

يمكن تحديد بداية ونهاية التنبؤ لإنشاء عدة إطارات زمنية في ملف GRIB واحد. يقسم محول WebP بعد ذلك بُعد `step` إلى طبقات مستقلة، ويستخدم عارض الخرائط الحالي شريط الزمن وزر تشغيل الحركة لعرض الإطارات. ابدأ بنطاق قصير مثل 24–48 ساعة ومتغير واحد مثل `msl` قبل طلب نطاقات وحقول أكبر.

## التثبيت

يضيف المشروع `ecmwf-opendata` إلى متطلبات Python. بعد تحديث البيئة:

```powershell
python -m pip install -r requirements.txt
```

## مثال تنزيل انتقائي

```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.sources.ecmwf_open_data --model ifs --resolution 0p25 --time 0 --step 6 --param 2t 10u 10v --output downloads/ecmwf/ifs.grib2
```

يمكن تحديد تاريخ تشغيل باستخدام `--date YYYY-MM-DD`. يجب مراجعة توفر الدورة والمتغيرات وخطوات التنبؤ في كتالوج ECMWF قبل طلب التنزيل.

## المخرجات وسلامة البيانات

- ينشأ الملف أولاً بامتداد `.part`.
- لا يُنشر الملف النهائي إلا بعد اجتياز فحص GRIB.
- ينشأ ملف `.source.json` بجوار الملف، يتضمن النموذج والطلب والحجم وSHA-256 ووقت الاسترجاع.
- ينشئ CLI ملف `.source.json` يتضمن مصدر البيانات ووقت التشغيل الفعلي وبصمة SHA-256 ونص الإسناد والترخيص؛ أما واجهة سطح المكتب فتسجل الملف أيضاً في سجل حالة الملفات SQLite مع الحجم والبصمة والمسار.
- تنتقل بيانات الإسناد إلى كل طبقة خريطة، ويعرضها عارض الخرائط بجانب معلومات الحقل: ECMWF بوصفه منتج البيانات، ومصدر الوصول (ECMWF أو AWS)، ورابط CC BY 4.0، وبيان التعديلات وإخلاء المسؤولية.

## التحويل إلى الخرائط

بعد التنزيل، استخدم محول GRIB الموجود في WebP:

```powershell
$env:PYTHONPATH = "src"
python -m ecmwf_collector.tools.grib_to_map downloads/ecmwf/ifs.grib2 --output-dir output/map_data/ecmwf
```

التحويل يدعم الحقول والشبكات التي يدعمها المحول الحالي فقط؛ اجتياز فحص GRIB لا يعني تلقائياً أن كل شبكة أو حقل قابل للرسم.

## اختبار حي اختياري

أُضيف سير عمل يدوي باسم **ECMWF Open Data live integration smoke test** في `.github/workflows/ecmwf-open-data-live-smoke.yml`، ويصبح قابلاً للتشغيل من واجهة GitHub Actions بعد دمج ملف سير العمل إلى الفرع الافتراضي. كما أضيف فحص حي مشروط لطلب الدمج الخاص بهذا التكامل في `.github/workflows/tests.yml`. اختر IFS أو AIFS Single أو AIFS Ensemble عند تشغيل الاختبار اليدوي. ينزل الاختبار حقل ضغط متوسط مستوى البحر `msl` لخطوة 24 ساعة، ويتحقق من GRIB2، ثم يحوله إلى PNG وNPZ وmanifest ويرفع المخرجات كـ artifact. هذا الاختبار لم يُشغّل بعد من هذه الجلسة؛ يجب تشغيله والتحقق من نتيجته قبل إعلان نجاح التنزيل الحي.

## الترخيص

تتطلب بيانات ECMWF Open Data الإسناد وفق CC BY 4.0 وشروط ECMWF الإضافية. يعرض WebP الإسناد داخل معلومات طبقة الخريطة ويحتفظ به في ملف المصدر. لا تحذف الإسناد عند إعادة نشر الخرائط، ولا تُضمّن بيانات التنزيل في Git. راجع [شروط استخدام بيانات ECMWF](https://apps.ecmwf.int/datasets/licences/general/) و[إرشادات الإسناد](https://confluence.ecmwf.int/spaces/DAC/pages/576396026/How+can+I+attribute+and+cite+ECMWF+data).
