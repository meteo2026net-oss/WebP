# الاعتمادية والباك إند الذكي للعرض متعدد القنوات

## الهدف المعماري
مصدر البيانات لا يتصل مباشرة بواجهة الخريطة أو بطاقة الطقس. تمر البيانات عبر الاستيعاب والتحقق والمعالجة والفهرسة والتخزين، ثم تُقدَّم عبر خدمات عرض مستقلة. بذلك تستهلك الخرائط والبطاقات والنقاط والمسارات حقلاً موحداً بدلاً من تكرار فك ملفات GRIB لكل شاشة.

## خط البيانات
1. موصلات مصادر الرصد والتنبؤات.
2. مهام استيعاب ذات معرّف ثابت وحالة ومحاولات وأوقات.
3. التحقق من الحجم والبنية وSHA-256 ووقت التشغيل ووقت الصلاحية والمتغير والمستوى والوحدة والإحداثيات.
4. فك GRIB/NetCDF وتوحيد الشبكة والوحدات وإنتاج الحقول المشتقة.
5. تخزين الحقول الشبكية الكبيرة كملفات NetCDF/Zarr أو كائنات؛ PostgreSQL/PostGIS للفهرسة والبيانات الوصفية والاستعلام المكاني والمهام.
6. API للكتالوج والطبقات والبلاطات وقيم النقاط وبطاقات الطقس والمسارات والتصدير.
7. عميل ويب/PWA وعميل سطح مكتب مع واجهات متجاوبة وكاش محلي.

## عقد البيانات
كل حقل منشور يحمل dataset_id وsource وmodel وrun_time وvalid_time وvariable وlevel وunit وgrid وcrs وbounds وresolution وchecksum وquality_status وcreated_at. يظل وقت تشغيل النموذج منفصلاً عن وقت صلاحية التنبؤ. لا تُنشر طبقة دون وحدة وأساليب تفسير ومدى زمني ومصدر معروف.

## خدمات العرض المقترحة
- GET /api/v1/catalog: المصادر والنماذج والتشغيلات والمنتجات.
- GET /api/v1/layers: الطبقات والوحدات والمستويات والأساطير.
- GET /api/v1/tiles/{layer}/{z}/{x}/{y}: بلاطات الخرائط.
- GET /api/v1/point: قيمة نقطة مع الوقت والوحدة والمصدر.
- GET /api/v1/weather-cards: بطاقات مدينة أو محطة أو إحداثيات.
- GET /api/v1/routes: الطقس على طول مسار سفر.
- POST /api/v1/exports وGET /api/v1/jobs/{id}: تصدير غير متزامن ومتابعة المهمة.

هذه عقود تصميم وليست API منشورة حالياً.

## سياسة الانقطاع والاستعادة
- الكتابة إلى ملف مؤقت مع checkpoint يحوي URL وETag/Last-Modified.
- استخدام Range وIf-Range عند دعم المصدر، والتحقق من Content-Range قبل الإضافة.
- إذا تجاهل الخادم Range وأعاد 200، يبدأ الملف من الصفر لتجنب تكرار البايتات.
- إعادة محاولة تلقائية للأخطاء العابرة وانقطاعات النقل وHTTP 408/429/500/502/503/504، بتأخير تصاعدي محدود.
- عدم تكرار أخطاء المصادقة والطلبات غير الصالحة وأخطاء سلامة الملف.
- لا يُنشر الملف النهائي إلا بعد التحقق والنقل الذري.
- عند عدم الاتصال، تعرض الواجهة آخر نسخة مخزنة مع وقتها وعلامة stale واضحة.
- بعد عودة الشبكة، تستأنف المهام المؤهلة مع حد للتزامن ومنع تكرار المهمة.

## الأداء
- لا ترسل ملفات GRIB الخام إلى المتصفح.
- إنتاج البلاطات والمشتقات مرة واحدة لكل dataset/layer/valid-time وإعادة استخدامها.
- مفاتيح الكاش تتضمن نسخة البيانات والطبقة ووقت الصلاحية ونطاق البلاطة.
- دعم ETag وطلبات conditional وضغط HTTP والتقسيم والصفحات.
- تشغيل فك الترميز وإنتاج البلاطات في workers خارج طلبات API.
- مراقبة زمن الاستجابة وcache hit ratio وطول queue وزمن المعالجة وعدد retries وأخطاء المصادر.

## مراحل التنفيذ
1. استقرار التنزيل والاستكمال وإعادة المحاولة.
2. سجل مهام دائم واستعادة المهام بعد إعادة التشغيل.
3. كتالوج حقول وبيانات وصفية موحدة.
4. تشغيل PostGIS ومخزن الحقول.
5. API للكتالوج والنقاط والبطاقات والتصدير.
6. خدمة البلاطات والخرائط المتحركة والطبقات.
7. الطقس على طول مسارات السفر.
8. PWA/عملاء متعددة الأجهزة واختبارات أداء وانقطاع الشبكة.

## حدود الحالة الحالية
الموجود حالياً أساس موصلات ومعالجة وملفات GRIB ومخطط قاعدة بيانات أولي. هذه الإضافة لا تعني أن API أو التخزين السحابي أو واجهة الخرائط المتعددة أو خرائط السفر قد نُشرت؛ تلك مراحل تنفيذ لاحقة.


## مقارنة النماذج ومحطة اعتماد المتنبئ

تُعرض المقارنات عبر جلسة محفوظة تجمع حقولاً متوافقة في المتغير والمستوى والوحدة ووقت الصلاحية، مع مقارنة خرائط A/B والفرق والسلاسل الزمنية والمقاطع والنقاط. عند اختلاف الشبكات، توثق طريقة إعادة الإسقاط/الاستيفاء. وتبقى مقاييس التحقق من الرصد منفصلة عن مجرد فرق نموذجين.

واجهة الخرائط والبطاقات هي محطة مراجعة للمتنبئين قبل النشر:
- البيانات المعالجة تدخل قائمة مراجعة غير معتمدة.
- يستطيع المراجع فحص الطبقات والبطاقات والمصدر والأوقات والوحدات ومقارنة النماذج وإضافة الملاحظات.
- حالات المراجعة: pending / in_review / approved / rejected / changes_requested.
- يسجل كل قرار هوية المراجع ووقته وسببه وإصدار البيانات.
- لا تظهر البيانات في واجهات النشر إلا بعد نجاح فحوص الجودة والاعتماد البشري.
- أي إعادة معالجة أو تغيير في نسخة البيانات يعيدها إلى المراجعة.

هذه الجداول والعقود تضيف أساساً للميزة؛ لكنها لا تعني أن واجهة المراجعة أو API قد نُفذت ونُشرت بعد.
