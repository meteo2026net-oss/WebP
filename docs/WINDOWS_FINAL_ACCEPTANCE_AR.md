# قائمة القبول النهائي — ECMWFWebP على Windows

هذه القائمة مخصصة لاختبار الحزمة المحمولة على Windows 10/11 x64. لا تعتبر اختبارات GitHub Actions بديلاً عن هذه التجربة الميدانية.

## 1. تثبيت الحزمة المحمولة وتشغيلها

1. نزّل ملف `ECMWFWebP-Windows-x64.zip` من أحدث تشغيل Windows ناجح في تبويب Actions.
2. احتفظ بملف ZIP الأصلي، ثم فك ضغطه كاملاً إلى مجلد مستقل، مثلاً `C:\\ECMWFWebP`.
3. تحقق من وجود `ECMWFWebP.exe` و`START.bat` و`SHA256SUMS.txt` في جذر المجلد.
4. من PowerShell داخل مجلد الحزمة، تحقق من البصمات باستخدام:

   ```powershell
   Get-Content .\\SHA256SUMS.txt
   Get-FileHash .\\ECMWFWebP.exe -Algorithm SHA256
   ```

   قارن بصمة EXE بالسطر المطابق في الملف. لا تشغّل الحزمة إذا اختلفت البصمة أو ظهر تحذير أمني غير مفهوم؛ لا تتجاوز حماية Windows لمجرد إكمال الاختبار.
5. شغّل أداة التحقق المرفقة من PowerShell داخل مجلد الحزمة:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\\Verify-ECMWFWebP.ps1
   ```
   تتحقق الأداة من جميع بصمات ملفات الحزمة وتغطية manifest، وتجربة تشغيل EXE، وإمكانية الكتابة في مجلد بيانات المستخدم، واستجابة خادم الخرائط وملفات HTML/CSS/JS. تنشئ تقريراً محلياً لا يتضمن كلمات المرور أو سلاسل الاتصال داخل:
   يعمل اختبار تشغيل الواجهة في مجلد بيانات مؤقت وبوضع SQLite معزول؛ لذلك لا يقرأ اتصال PostgreSQL المحفوظ ولا يتصل بخادم ECMWF أو قاعدة بيانات المستخدم، ولا يغيّر قاعدة الحالة الأصلية.
   `%LOCALAPPDATA%\\ECMWFWebP\\logs`
6. بعد نجاح الفحص، شغّل `START.bat` لفتح التطبيق. لا تنقل EXE وحده؛ يجب إبقاء ملفات المجلد المساندة بجواره.

## 2. فحص أول تشغيل وقاعدة SQLite

1. افتح زر **حالة قاعدة البيانات**. عند التشغيل الافتراضي ينبغي أن تظهر SQLite.
2. دوّن عدد السجلات الظاهر.
3. أنشئ نسخة من زر **نسخ احتياطي للسجل**.
4. تحقق من ظهور ملف النسخة داخل:
   `%LOCALAPPDATA%\\ECMWFWebP\\state\\backups`
5. لا تختبر الاستعادة على سجل عمل مهم. استخدم ملف قاعدة اختبار أو احتفظ بنسخة مستقلة مؤكدة قبل الضغط على **استعادة نسخة SQLite**.

## 3. اختبار واجهة المهام الخلفية

1. ابدأ عملية نسخ احتياطي أو معالجة ملف اختبار.
2. حاول إغلاق النافذة أثناء تنفيذ المهمة.
3. اختر الانتظار، وتأكد أن النافذة تبقى مفتوحة حتى انتهاء العامل ثم تُغلق.
4. اختبر فشل تنزيل في بيئة اختبار غير حساسة، وتأكد من إرجاع أزرار الإيقاف المؤقت والإيقاف إلى حالتها الطبيعية ومن بقاء الملفات المكتملة.

## 4. تثبيت PostgreSQL وترحيل السجل (اختياري)

1. تأكد من وجود Windows Package Manager (`winget`). يستخدم زر **تثبيت PostgreSQL** مثبّت EDB الرسمي التفاعلي لـ PostgreSQL 16.
2. أكمل نافذة المثبّت وحدد كلمة مرور المدير بنفسك. لا يستخدم التطبيق كلمة مرور افتراضية ولا يحفظ كلمة مرور المدير.
3. أنشئ قاعدة بيانات مخصصة للاختبار من pgAdmin أو أداة PostgreSQL الرسمية؛ زر التثبيت يثبت الخادم والخدمة لكنه لا ينشئ اسم قاعدة تطبيق تختاره.
4. أنشئ أولاً نسخة SQLite احتياطية وتأكد من سلامتها.
5. استخدم زر **ربط PostgreSQL ونقل السجل** وأدخل سلسلة اتصال المدير في حقل الإدخال المخفي. لا ترسل سلسلة الاتصال أو كلمة المرور في محادثة أو سجل أو ملف إعدادات.
6. بعد الترحيل، افتح **حالة قاعدة البيانات** وتحقق من أن PostgreSQL نشط وأن عدد السجلات يطابق العدد الذي دوّنته من SQLite.
7. تأكد من بقاء ملف SQLite الأصلي ونسخته الاحتياطية.

## 5. اختبار نسخ PostgreSQL واستعادته

1. تأكد من أن أدوات `pg_dump` و`pg_restore` من الإصدار الرئيسي نفسه.
2. أنشئ نسخة PostgreSQL؛ يجب أن ينتج ملف `.dump` وملف JSON جانبي `.dump.json`.
3. استخدم قاعدة بيانات اختبار منفصلة للاستعادة؛ لا تختبر الاستعادة على قاعدة إنتاج أو قاعدة تحتوي بيانات مهمة.
4. عند الاستعادة، أدخل اتصال حساب PostgreSQL بصلاحية `SUPERUSER` في الحقل المخفي. حساب مالك القاعدة وحده لا يكفي للاستعادة الكاملة.
5. تحقق من أن التطبيق يرفض نسخة لا تطابق قاعدة الاتصال، وينشئ نسخة أمان قبل الاستبدال، ويعرض عدد السجلات الذي قرأه حساب التطبيق بعد الاستعادة.

## 6. اختبار ECMWF والخرائط الحقيقية

1. أدخل بيانات ECMWF المصرح بها داخل التطبيق فقط، ثم اضغط **اختبار الاتصال**.
2. ابدأ باستعراض الخادم دون تنزيل، ثم عاين خطة التنزيل وحدد ملفاً واحداً صغيراً أو منتج اختبار مناسباً.
3. بعد تنزيل ملف GRIB مسموح بتداوله، اختبر الفحص والتحويل إلى طبقات، ثم افتح عارض الخرائط المحلي.
4. قارن قيم الحقول والوحدات ووقت الصلاحية مع مصدر موثوق قبل الاعتماد العلمي على الخريطة.
5. لا ترفع بيانات الاعتماد أو ملفات GRIB المقيدة أو قواعد البيانات إلى GitHub.

## ما الذي يثبت اكتمال الإصدار؟

يُعد الإصدار مقبولاً ميدانياً بعد نجاح الأقسام المناسبة أعلاه على جهاز Windows مستقل، مع نجاح اتصال ECMWF الحقيقي وتجربة PostgreSQL على قاعدة اختبار منفصلة عند تفعيل هذا الخيار. نجاح CI يثبت البناء والاختبارات الآلية وتشغيل EXE وخادم الخرائط على runner، لكنه لا يثبت صلاحية بيانات اعتماد المستخدم أو الوصول إلى خادم ECMWF أو إعداد PostgreSQL على جهازه.
