# مدير اتصالات قواعد البيانات — المرحلة الأولى

## ما أُضيف

- سجل اتصالات منفصل في `config/database-profiles.json`، يحتوي بيانات التعريف فقط.
- كلمات مرور PostgreSQL وMySQL وMariaDB تحفظ عبر `SecretStore` في مخزن أسرار نظام التشغيل باستخدام مفتاح خاص بكل اتصال.
- واجهة سطح مكتب لإضافة الاتصالات وتعديلها واختبارها وتفعيلها وتعطيلها وحذف تعريف الاتصال.
- اختبار SQLite يفتح الملف الموجود بوضع القراءة فقط، ولا ينشئ ملفاً جديداً.
- اختبار PostgreSQL ينفذ `SELECT 1` فقط؛ لا ينشئ قاعدة بيانات أو جدولاً ولا يغير المخطط.
- أساس توجيه مستقل لكل مزوّد/نموذج/منتج، مع قاعدة افتراضية اختيارية.
- تعطيل/حذف اتصال مستخدم في التوجيه لا يؤدي إلى تحويل صامت إلى قاعدة أخرى. حذف التعريف لا يحذف قاعدة البيانات أو ملفات CSV/GRIB.

## ما لم يُنفذ بعد

1. ربط توجيه النماذج بمسارات كتابة بيانات الطقس الفعلية؛ المرحلة الحالية تحفظ قواعد التوجيه وتعرضها فقط.
2. موصلات اتصال فعلية لـ MySQL وMariaDB، ومراجعة دعم SSL لكل موصل.
3. نقل/نسخ بيانات بين قواعد متعددة، الدمج المركزي، إزالة التكرار، وتوثيق المصدر.
4. تقارير أحجام قواعد البيانات والملفات ومراقبة مزامنة المصادر.
5. تحويل الاتصال الحالي المستخدم لسجل التنزيلات إلى ملف تعريف مُدار تلقائياً؛ يبقى مسار SQLite/PostgreSQL الحالي كما هو حتى مرحلة ترحيل مستقلة مع نسخة احتياطية واختبارات مطابقة.

## ملفات البيانات

- `config/database-profiles.json`: أسماء الاتصالات ومضيفوها وقواعدها ومراجع مفاتيح الأسرار فقط.
- `config/database-routing.json`: تعيينات النموذج إلى معرّف ملف الاتصال فقط.
- لا تحفظ هذه الملفات كلمة مرور أو DSN يحتوي كلمة مرور.

## ضمانات السلامة

- لا تُنفذ هذه المرحلة أي ترحيل تلقائي ولا تكتب إلى قواعد بيانات المستخدم.
- لا تُحذف قاعدة SQLite الحالية أو قاعدة PostgreSQL الحالية عند حذف تعريف اتصال من الواجهة.
- يجب أن يسبق ربط أي مسار تنزيل جديد بقاعدة متعددة اختبار تكامل على قاعدة اختبار منفصلة، ثم اختبار ترحيل/استعادة قبل اعتماده.

## Windows CI follow-up

أظهر أول تشغيل Windows بعد إضافة اختبار اتصال SQLite أن استخدام مدير سياق `sqlite3.Connection` ينفذ commit/rollback لكنه لا يغلق الاتصال تلقائياً؛ أدى ذلك إلى قفل ملف قاعدة الاختبار ومنع تنظيف المجلد المؤقت على Windows. تم تعديل اختبار الاتصال لإغلاق المقبض صراحةً داخل `finally` في commit `27a63e510f8968769b64631ec53bdddcc1b77c7a`.

- Linux Python CI على التغييرات السابقة نجح.
- Windows CI اكتشف مشكلة قفل الملف في الاختبارات (484 اختباراً، خطأ واحد في تنظيف ملف SQLite).
- إصلاح إغلاق الاتصال محفوظ، لكن يلزم تشغيل Windows CI جديد على هذا الإصلاح قبل إعلان نجاح الحزمة.

## مؤشرات صحة قواعد البيانات — توسعة المرحلة الأولى

- أضيفت خدمة `database_health.py` لفحص SQLite وPostgreSQL في وضع القراءة فقط.
- تعرض الواجهة حالة الاتصال، وجود جدول تتبع الملفات، عدد السجلات، المكتمل والفاشل، الحجم المحلي المسجل، وآخر تحديث.
- يجري الفحص في عامل خلفي حتى لا تتجمد الواجهة أثناء اتصالات الشبكة.
- لا تُنفذ الخدمة أي DDL أو DML، ولا تنشئ قاعدة أو جدولاً أو ملف SQLite.
- الأرقام المعروضة تخص جدول تتبع التنزيلات `files` فقط؛ لا تمثل عدد ملفات CSV/GRIB على القرص ولا حجم بيانات الطقس داخلها.
- أضيفت اختبارات لحساب الأعداد والأحجام، وغياب الملف/الجدول، وتعطيل الاتصال، والتأكد من عدم تغيير ملف SQLite.
- موصلات MySQL/MariaDB ما زالت غير متاحة؛ تظهر حالتها بوضوح ولا يُدّعى نجاح الاتصال بها.

## معالجة أمان حذف بيانات الاعتماد

إذا رفض مخزن أسرار نظام التشغيل حذف كلمة مرور اتصال، يحتفظ البرنامج بتعريف الاتصال حتى يمكن إعادة المحاولة؛ لا يحذف التعريف أولاً ويترك كلمة مرور يتيمة. أضيف اختبار انحدار لهذه الحالة.
