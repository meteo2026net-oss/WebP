# معمارية منصة الطقس متعددة الأجهزة — خارطة التنفيذ

## الهدف

تحويل WebP من جامع ملفات سطح مكتب إلى منصة أرصاد قابلة للتشغيل عبر المتصفح والهاتف والكمبيوتر، مع إبقاء محرك جمع GRIB والتحقق والمعالجة العلمية قابلاً لإعادة الاستخدام.

هذه الخطة تستلهم **الأنماط العامة** الظاهرة في منصات الخرائط الجوية: اختيار النموذج والطبقة والمستوى، مفتاح ألوان ووحدات، منتقي قيم عند النقر، خط زمني متحرك، وخطوط تساوي الضغط/الحرارة. لا تعتمد على شيفرة Windy الخاصة أو واجهات غير موثقة أو إعادة استخدام أصولها.

## ما تعنيه «مثل Windy» وظيفياً

- خريطة تفاعلية قابلة للتكبير والتحريك.
- اختيار النموذج والتشغيل ووقت الصلاحية وساعة التنبؤ والمستوى الرأسي.
- كتالوج طبقات مع legend ووحدات ومقاييس لونية وشفافية.
- حركة زمنية للحقول، وparticles للرياح عندما تتوفر مركبات U/V متوافقة.
- قراءة قيمة نقطة على الخريطة بالاستيفاء الأقرب أو الثنائي.
- خطوط تساوي الضغط/الارتفاع الجهدي والطبقات المجمعة مثل الهطول التراكمي.
- إظهار مصدر البيانات ودقتها وتوقيت التشغيل والصلاحية والتحقق من الجودة.

Windy تنشر Map Forecast API بواجهة طبقات وخطوط تساوي وlegend وpicker، وتذكر وثائقها اختيار overlay وlevel والنموذج. واجهتها API تجارية بشروطها؛ هذا المشروع سيبني محركه المستقل أو يستخدم مزوداً مرخصاً عند اختيار ذلك. راجع:
- https://api.windy.com/map-forecast/docs
- https://api.windy.com/map-forecast/tutorials/parameters
- https://api.windy.com/map-forecast/pricing

## المعمارية المستهدفة

```
مصادر النماذج (ECMWF / NOAA GFS / NOAA GEFS / مصادر أخرى مرخصة)
        |
        v
منسق التنزيل: queue + concurrency + retries + HTTP Range/FTP REST
        |
        v
ملفات أصلية موثقة: GRIB2 / NetCDF + SHA-256 + provenance
        |
        v
معالجة علمية: ecCodes/cfgrib/xarray + توحيد grid/units/time/levels
        |
        +---------------------> مخزن كائنات للملفات والبيانات المقطعة (Zarr/NetCDF)
        |
        v
PostgreSQL + PostGIS: catalog / runs / fields / grids / assets / jobs
        |
        v
خدمات API + tile renderer + point sampling + legends
        |
        v
واجهة ويب PWA متجاوبة + MapLibre/WebGL + timeline + wind particles
        |
        +--> Desktop wrapper اختياري
        +--> Mobile installable PWA
```

## تخزين البيانات: لا تضع كل خلية في صف SQL

الحقول العددية الشبكية عالمية وكبيرة جداً. تخزين كل قيمة كصف مستقل في PostgreSQL يضخم القاعدة ويبطئ الاستعلام. لذلك:
- ملفات المصدر الأصلية تحفظ كما هي في object storage أو نظام ملفات محلي أثناء التطوير.
- البيانات المقطعة تحفظ بصيغة Zarr/NetCDF مع chunking حسب الوقت والمستوى والمجال.
- PostgreSQL/PostGIS يحتفظ بالفهرس الوصفي، حدود الشبكة، الإحداثيات المرجعية، المتغيرات، الوحدات، التشغيل، وقت الصلاحية، المراجع، checksums، وحالة المعالجة.
- خادم الطبقات يقرأ chunks المطلوبة فقط ويصدر tiles/rasters مناسبة للعرض.
- لا تُصدّر قيم نموذج إلى قاعدة الإنتاج قبل اجتياز فحص الوحدات والشبكة والوقت والـ checksum.

## مخطط البيانات

ملف `sql/weather_platform_schema.sql` يضيف الجداول الأساسية:
- `weather.model`: تعريف النموذج والمصدر والدقة.
- `weather.forecast_run`: دورة التشغيل وتوقيت الإصدار.
- `weather.grid`: تعريف الشبكة وحدودها.
- `weather.variable` و`weather.level`: قاموس المتغيرات والمستويات والوحدات.
- `weather.field`: حقل متغير واحد عند تشغيل/مستوى/ساعة محددة مع URI للبيانات.
- `weather.asset`: ملفات GRIB2/NetCDF/Zarr/tiles والبصمة والحجم.
- `weather.tile_cache`: فهرس tiles عند تفعيل التخزين المؤقت.
- `weather.ingestion_job`: تتبع التنزيل والاستكمال وإعادة المحاولة.

يتطلب نوع geometry تفعيل PostGIS بواسطة مسؤول قاعدة البيانات قبل تطبيق المخطط. لا تستخدم بيانات اعتماد مدير قاعدة البيانات داخل التطبيق.

## واجهات API المقترحة

- `GET /api/v1/catalog/models`
- `GET /api/v1/catalog/layers?model=...`
- `GET /api/v1/runs?model=...`
- `GET /api/v1/fields?run=...&variable=...&level=...&lead=...`
- `GET /api/v1/tiles/{field_id}/{z}/{x}/{y}`
- `GET /api/v1/point?field_id=...&lat=...&lon=...&method=bilinear`
- `GET /api/v1/legend/{field_id}`
- `POST /api/v1/exports` لإنشاء مهمة تصدير قابلة للاستعلام عن حالتها.
- `GET /api/v1/jobs/{job_id}` لمتابعة التنزيل والمعالجة.

يجب أن تكون كل الاستجابات صريحة في units وvalid_time وmodel وrun وlevel وsource؛ لا يُسمح بإخفاء نقص البيانات أو تبديل الوحدات بصمت.

## سرعة التنزيل والاستكمال

- حد اتصالات متزامنة قابل للضبط لكل مصدر، مع حد إجمالي يحمي الخادم والشبكة.
- HTTP Range مع If-Range وETag/Last-Modified؛ لا يُلحق الجزء إلا إذا أكد الخادم موضع Content-Range.
- FTP REST حيث يدعمه الخادم، وإعادة التحقق من حجم المصدر.
- checkpoint مستقل عن ملف البيانات، يتضمن URL والـ validator وعدد البايتات.
- إعادة محاولة بتأخير تصاعدي، وتسجيل سرعة النقل ومتوسطها والبايتات المتبقية.
- فحص الحجم والإطار GRIB2 وSHA-256 قبل النشر النهائي.
- لا يعني دعم Range أن كل مصدر يسمح بالاستكمال؛ عند رفضه يعاد التنزيل بأمان من الصفر.

## دعم الأجهزة

الهدف الأساسي هو واجهة ويب PWA:
- تصميم RTL ومتجاوب للهاتف واللوحي والكمبيوتر.
- MapLibre GL JS/WebGL للخرائط، مع fallback عند عدم توفر WebGL.
- Web Workers للمعالجة البصرية التي لا يجب أن تجمد الواجهة.
- Service Worker لتخزين ملفات الواجهة والبيانات المختارة مؤقتاً، وليس تنزيل توقعات عالمية ضخمة تلقائياً.
- API منفصل عن واجهة المستخدم؛ يمكن استضافته على خادم Linux/Windows أو خدمة سحابية.
- تطبيق سطح المكتب يصبح غلافاً اختيارياً، وليس الطريق الوحيد لاستخدام النظام.

«كل الأجهزة» تعني المتصفحات الحديثة المتوافقة؛ الأداء يعتمد على الذاكرة وGPU والشبكة، وبعض الطبقات الثقيلة ستحتاج تقليل الدقة أو المجال على الهواتف.

## مراحل التنفيذ والتحقق

1. **الاستكمال والتنزيل:** استكمال HTTP/FTP، retries، قياس السرعة، اختبارات انقطاع حقيقية.
2. **كتالوج علمي موحد:** قاموس متغيرات/مستويات/وحدات وربط GRIB metadata بالطبقات.
3. **قاعدة البيانات والتصدير:** تطبيق المخطط، migrations، bulk ingestion، وفهرسة مكانية.
4. **محرك الطبقات:** tiles، legends، isolines، point sampling، timeline.
5. **واجهة PWA:** تصميم متجاوب وMapLibre وحركة الرياح.
6. **توسيع المصادر:** إضافة نماذج أخرى فقط مع موصلات قابلة للاختبار وبيانات مرخصة.
7. **اختبارات ميدانية:** ملفات حقيقية، أجهزة فعلية، ضغط، استعادة، مراقبة جودة.

## معيار الإنجاز

لا تُعلن طبقة «جاهزة» لمجرد ظهور اسمها في القائمة. يجب أن يتوفر لها:
1. مصدر/نموذج معروف وتوقيت تشغيل وصلاحية.
2. متغير ومستوى ووحدة معتمدة.
3. ملف أو dataset فعلي اجتاز التحقق.
4. تحويل شبكي/tiles صحيح مع legend.
5. قراءة نقطة تطابق قيمة المصدر ضمن سماحية معلنة.
6. اختبار على الهاتف والكمبيوتر.
